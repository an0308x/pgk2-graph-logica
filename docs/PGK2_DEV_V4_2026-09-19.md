## Prespecified design

Nine arms: three training evidence policies crossed with three model/objective
arms. One seed (2026); no learning-rate search.

| Evidence policy | Meaning |
| --- | --- |
| cap 0 | Unchanged v3 observed-control evidence; zero competitor reads excluded |
| cap 1 | Additional weak competition evidence for zero competitor reads, assuming a control-count range of 0–1 |
| cap 5 | Same sensitivity test with the broader assumed range 0–5 |

| Model/objective | Learning rate | Auxiliary weight |
| --- | ---: | ---: |
| Linear Morgan-2048 | 0.001 | None |
| Graph LogiCA, DEL ranking only | 0.00003 | 0 |
| Graph LogiCA, DEL ranking + ligand reconstruction | 0.00003 | 0.01 |

Two maximum passes across all 64 shards. Each pass visits every eligible
training pool in each shard in batches of 32 (a singleton tail merges into the
previous batch). A channel pool with fewer than two rows cannot form a pair.
Coverage is reported explicitly; early stopping can end a pass before all shards.
This is not an arbitrary 308/241-compound subset, nor a claim of full-library
auxiliary exposure. Existing molecular graphs are reused.

Auxiliary arms draw four 64-molecule batches from the training split of the
current shard per ranking batch. Ranking loss is multiplied by four; auxiliary
losses are summed with weight 0.01. This preserves the old intended exposure/
loss ratio but accumulates into one optimizer step, so it is NOT an exact replay
of the previous four separate v3 updates. Ranking dropout seeds are matched
across objective arms. Gradient norms and shared-parameter cosine similarity
are sampled every 200 steps before clipping. These diagnose instantaneous
gradient balance, not proof of a causal mechanism.

Fixed inputs: full-sequence ESM, 2D full-ligand graphs, the same compounds-21/47
pocket ensemble and interface mask, frozen language-model encoders, and the
existing shared scaffold split. No pose generation or graph rebuild.

## Zero-count assumptions and data inspection

Inspected both released Parquet schemas and file metadata. They contain
compound/SMILES, counts and z-score columns (plus historic hits in selection),
but no sequencing-depth fields or assay-specific size factors. Released-table
column sums are not established sequencing depths. No depth normalization is
invented and no normalized-Z aggregation is used.

For added zero-competitor rows, require mean target reads >=5. Use the assumed
proxy interval `[log1p(target)-log1p(cap), log1p(target)]`. Rank a pair only if
the two intervals are separated by at least log(2). This interval is a
sensitivity assumption, NOT a statistical confidence/credible interval and
does not account for all target-count uncertainty.

Added confidence is `0.05 * T/(T+20) / (1+historic_hits) /
(1+max(mean_selection_NTC, mean_supplement_NTC)/T)`. Thus it never reaches 0.05.
Observed-control evidence is unchanged, NTC zeros remain excluded, duplicates
retain mean-per-source-row semantics, and no new binary inhibitor labels are
created. Constants are prespecified heuristics, not fitted probabilities.

## Checkpoint selection and boundaries

Evaluate the initial checkpoint and after every 16 training shards. Select
strict improvements in the original combined confidence-scaled development
pair loss; ties retain the earlier checkpoint. Stop after four consecutive
non-improving checks, or two passes. Competition ordering is separately reported,
not substituted for the prespecified selection metric after seeing results.

Every evaluation reuses the exact original observed-control development pairs.
Their SHA-256 identity and starting graph competition score must reproduce the
completed baseline audit. Random-number state is preserved across evaluation.
Every saved adapter remains `candidate_scoring_allowed: false`.

Important limitation: this fixed evaluator can compare generalization on
observed controls but cannot establish whether newly included zero-read
compounds are real inhibitors. A useful development result would justify a
further review, not automatic challenge submission. The holdout has historical
exposure from v3, so it is not an untouched final external test.

The 128-token ligand-language-model truncation limitation also remains.

## Implementation

- `src/logica_binding/development_protocol.py`: bounded evidence, interval ranking,
  full eligible-pool traversal, checkpoint selection and gradient diagnostics.
- `scripts/run_pgk2_development.py`: development-only runner; initial/intermediate
  selection; no holdout evaluation path; atomic best/last adapters.
- `scripts/submit_pgk2_development.slurm`: nine GPU array tasks, at most two
  concurrent, any available GPU type, one-hour limit per task. No A100 request.
- `tests/test_pgk2_development.py`: point-loss/gradient parity, uncertainty
  separation, zero weights, split boundaries, singleton coverage, selection,
  gradient diagnostics and real-checkpoint CPU smoke tests.
